Execution Engine
A series in seven parts

Building a query execution engine

From evaluating one expression against one row to a planner that reads statistics and compiles a query into bytecode you can pause, save, and resume.

A SQL query is a tree. Something has to turn that tree into rows. This series builds that something from scratch, in small steps, in both Go and Clojure. It's at the level of sqlglot's Python SQL engine: small enough to read in an afternoon, real enough that the ideas carry over to SQLite, Postgres, and DuckDB.

Every part has interactive figures. Step through them; they're the point.

  1. ExpressionsRows and values. Evaluating an expression tree, three-valued logic, and compiling a tree into closures.
  2. IteratorsOperators as pull iterators: Scan, Filter, Project, Limit. Why the Volcano model streams.
  3. JoinsNested loop, hash, and sort-merge joins, and what outer joins add.
  4. Aggregation & sortingHash vs. sort aggregation, external merge sort, and top-N with a heap.
  5. IndexesB+trees, index scans, and the index nested-loop join.
  6. Statistics & planningHistograms, selectivity, cardinality estimates, a cost model, and join ordering by dynamic programming.
  7. BytecodeCompiling plans to a register VM like SQLite's, and why that makes queries resumable.

Practice

Reading about a hash join isn't the same as writing one. Three things help it stick:

  • Predict, then reveal. Figures ask for your guess before they show the answer. Being wrong first is the point.
  • Build it. EXERCISES.md lists the exercise track: every lesson's key functions with the bodies removed and the tests left in. Make go test ./exercises/lesson03/ (or the Clojure equivalent) pass.
  • Review. A few spaced-repetition cards a day from the parts you've read, mixed across parts. Each post also opens with a warm-up from the one before.

The code

Each part has a standalone lesson in go/lessonNN and clojure/src/lessonNN with a runnable demo. The integrated engine in go/engine and clojure/src/engine puts everything together: SQL text in, a parser, a planner that reads statistics, and two executors (iterators or bytecode) that must agree.

cd go && go run ./cmd/engine
cd clojure && clojure -M -m engine.main
